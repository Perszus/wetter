# Contributing to Wetter

Bug reports and patches are welcome. This file is the short version of what the
project expects; the reasoning lives in
[docs/design-principles.md](docs/design-principles.md).

## Getting it building

Requires JDK 17 and the Android SDK. Nothing else — no keys, no accounts, no
signing material.

```sh
./gradlew test            # every module's unit tests
./gradlew ktlintFormat    # fix formatting
./gradlew check           # tests, lint and formatting — what CI runs
./gradlew assembleDebug   # a runnable APK
```

`local.properties` is generated by Android Studio and is not in the repository.
If you build from the command line without it, set `ANDROID_HOME`.

## The module layout

```text
:app  ──▶  :data  ──▶  :domain
```

- **`:domain`** is a plain Kotlin library. Weather models, the provider
  abstraction, the selection policy and the solar geometry. It has no
  dependencies beyond the standard library, and that is the point — an Android
  or networking import appearing here means the code is in the wrong module.
- **`:data`** is an Android library. Provider implementations, the router that
  chooses between them, and caching. The concrete providers and the HTTP client
  are `internal`, so nothing outside can reach past `WeatherData`.
- **`:app`** is the application. Compose UI, the object graph, the activity.

The arrow only points one way, and the compiler enforces it. If you find
yourself wanting to point it the other way, that is worth raising in an issue
before writing the code.

## What a good patch looks like

**It explains why.** What the code does is visible in the diff. Why it does it
that way, and what you rejected, is not — and that is the part a reviewer and
the next person actually need. Comments in this codebase are written in that
spirit; please match it.

**It is tested where it can break.** Arithmetic, policy, mappers and the offline
contract have tests. Layout does not. Coverage is not a target — a test that
cannot fail is worse than no test, because it costs the same to maintain and
tells you nothing.

Where a test needs an absolute value, derive it in the test rather than pasting
one in. The solar tests do this: a reader can re-derive solar noon from a
longitude and the equation of time, and cannot re-derive a number copied off a
website.

**It does not widen the scope.** Fixing a bug and reformatting the file it lives
in makes the fix unreviewable. `./gradlew ktlintFormat` is there so formatting is
never a judgement call, but run it as its own commit if it touches much.

**It keeps abstraction earned.** An interface with one implementation needs a
reason — usually that a second is genuinely coming. There is no
dependency-injection framework here, no event bus and no charting library, and
adding one needs a case that names what it buys.

## Adding a weather provider

This is the extension point the architecture exists for, and it should not
require touching anything else.

1. **Read the terms first.** [docs/providers.md](docs/providers.md) has a
   checklist. This is the step that disqualifies most candidates, and doing it
   last wastes the implementation.
2. Add a package under `data/src/main/kotlin/…/data/provider/`, with the
   response types (`internal`), a mapper beside them, and the `WeatherProvider`
   implementation.
3. Declare capabilities honestly. If a field is documented but null in practice,
   leave it out. Take particular care with `hourlyHorizonHours`: it is how far
   the service is *genuinely* hour by hour, which is often much less than how
   far it forecasts.
4. Register it in `WeatherData.providers`. That is the whole integration.
5. Add a recorded response under `data/src/test/resources` and a mapper test
   covering its awkward parts — nulls, short arrays, changes of resolution —
   rather than its easy ones.
6. Add the attribution to `docs/providers.md` and the README.

## Dependencies

Every dependency must be free software with a licence compatible with the GPL,
and must be buildable from source by F-Droid. Nothing proprietary, nothing that
needs an API key baked into a public repository, and nothing from Google Play
Services.

A new dependency needs a sentence saying what it buys that the standard library
and what is already here do not.
