# Exhaustive Weather Visual-State Catalogue

A master catalogue of distinct weather conditions suitable for a weather app where each visual state is represented by a complete, dedicated image.

The catalogue contains 338 numbered states. `DAY` and `NIGHT` are explicit because each is a distinct complete visual scene.

# Recommended Visual-State Data Model

The catalogue above is the finite image catalogue. Meteorological input should remain compositional.

```typescript
interface WeatherVisualState {
    sky:
        | "clear"
        | "mostly_clear"
        | "partly_cloudy"
        | "mostly_cloudy"
        | "broken"
        | "overcast";

    precipitation:
        | "none"
        | "drizzle"
        | "rain"
        | "snow"
        | "snow_grains"
        | "ice_pellets"
        | "freezing_rain"
        | "freezing_drizzle"
        | "sleet"
        | "hail"
        | "snow_pellets"
        | "graupel"
        | "mixed";

    precipitationIntensity:
        | "none"
        | "light"
        | "moderate"
        | "heavy"
        | "very_heavy"
        | "torrential";

    precipitationCharacter:
        | "continuous"
        | "intermittent"
        | "showers";

    thunderstorm:
        | false
        | true
        | "severe"
        | "embedded"
        | "obscured";

    lightning:
        | "none"
        | "distant"
        | "visible";

    fog:
        | "none"
        | "mist"
        | "fog"
        | "dense"
        | "freezing"
        | "patchy"
        | "shallow";

    wind:
        | "calm"
        | "breezy"
        | "windy"
        | "strong"
        | "very_strong"
        | "gale"
        | "severe_gale"
        | "storm_force";

    windPhenomenon:
        | "none"
        | "squall"
        | "blowing_snow"
        | "drifting_snow"
        | "blowing_dust"
        | "blowing_sand"
        | "dust_whirl";

    visibility:
        | "normal"
        | "reduced"
        | "poor"
        | "very_poor"
        | "near_zero";

    exceptional:
        | "none"
        | "volcanic_ash"
        | "funnel_cloud"
        | "tornado"
        | "waterspout"
        | "duststorm"
        | "sandstorm"
        | "blizzard";

    illumination:
        | "day"
        | "dawn"
        | "dusk"
        | "night";

    season:
        | "spring"
        | "summer"
        | "autumn"
        | "winter";
```

## Canonical resolution rule

Provider data must be converted into the compositional state first:

```text
RAW PROVIDER DATA
        ↓
NORMALIZATION
        ↓
PHENOMENA DETECTION
        ↓
INTENSITY
        ↓
COMBINATION RESOLUTION
        ↓
VISUAL PRIORITY
        ↓
CANONICAL VISUAL STATE
        ↓
IMAGE ID
```

The image ID is therefore deterministic.

Example:

```text
heavy rain
+ thunder
+ lightning
+ strong wind
+ night
        ↓
THUNDERSTORM_HEAVY_RAIN_NIGHT
```

If a condition is sufficiently visually dominant, it should take precedence over generic conditions.

Example:

```text
fog + rain + thunderstorm
        ↓
OBSCURED_THUNDERSTORM_NIGHT
```

rather than trying to find an impossible image representing every phenomenon equally.

## Important distinction

The 338 catalogue entries are **visual states**, not every possible meteorological permutation.

The numerical weather engine can have vastly more combinations:

```text
temperature
humidity
pressure
wind
gust
precipitation rate
visibility
cloud layers
CAPE
radar reflectivity
etc.
```

Those numerical variables determine which canonical image is appropriate.

This keeps the image system exhaustive without requiring an infinite number of images.
